# 🏀 Баскетбол — матчи онлайн

Веб-приложение для баскетбольных матчей между живыми игроками: договорились
на площадке, открыли телефоны, бросаете по очереди и отмечаете попадания.
Счёт, очередь хода и таймер синхронизируются у всех участников в реальном
времени.

Без сборки и зависимостей: чистый HTML, CSS и JavaScript плюс Firebase
Realtime Database. Открывается как обычная страница и ставится на телефон
как приложение.

## Что умеет

**Матч**
- Броски по очереди: попал — бросаешь ещё, промахнулся — ход переходит дальше.
- Три способа определить победителя: свободный матч, на цель (N попаданий
  или очков) и на время.
- Продвинутый режим: броски с зон стоят 1, 2 или 3 очка.
- Таймер на ход с авто-промахом, пауза, отмена последнего броска.
- Отмечать броски может либо сам бросающий, либо только создатель матча.
- Живое табло, лента событий, быстрые реакции эмодзи, звук и вибрация.
- Тренировка в одиночку — когда соперника нет под рукой.

**Вокруг матча**
- Приглашения игрокам, лобби с обратным отсчётом и отметкой «в сети».
- Вход по ссылке: её можно кинуть в мессенджер кому угодно.
- Поздний вход и возвращение в матч, из которого вышел.
- История матчей с полным логом и фильтром, личные встречи с каждым
  соперником, рейтинг игроков, статистика и достижения.
- Ролик матча на 18 секунд: реплей бросков, слоу-мо решающего броска и
  карточка победителя — собирается прямо в браузере и скачивается файлом.

## Как запустить

Нужен любой статический сервер — открывать `index.html` с диска нельзя
из-за ограничений браузера на модули и service worker.

```bash
npx http-server -p 8080 -s .
# затем http://127.0.0.1:8080
```

### Своя база

В `scripts.js` вверху лежит `firebaseConfig`. Чтобы поднять своё окружение,
создайте проект в Firebase, включите Realtime Database и подставьте
`databaseURL` и `projectId`.

> **Внимание.** Сейчас приложение работает без Firebase Authentication, а
> значит правила базы не могут разграничить доступ: любой, кто знает адрес
> базы, может прочитать и изменить чужие данные. PIN хранится в виде
> несолёного самописного хэша, и при входе клиент выкачивает весь список
> пользователей. Для игры с друзьями этого хватает, но публично выкладывать
> в таком виде не стоит. Полноценное решение — Firebase Auth плюс правила
> базы и отдельный индекс ников, чтобы не выгружать всех пользователей.

## Структура

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка всех экранов и модальных окон |
| `style.css` | Оформление, тёмная тема на CSS-переменных |
| `scripts.js` | Вся логика: экраны, матч, статистика, генератор видео |
| `audio-clip.js` | 18 секунд трека в base64 для ролика, грузится лениво |
| `sw.js`, `manifest.json`, `icon.svg` | PWA: установка на телефон и офлайн-оболочка |
| `tests/` | Сквозные тесты в настоящем браузере |

## Данные в базе

```
users/{userId}              профиль, PIN-хэш, статистика, онлайн
matches/{matchId}           состав, настройки, счёт, события, реакции
invites/{userId}/{matchId}  приглашения
history/{userId}/{matchId}  личная история с полным логом матча
userMatches/{userId}        индекс незавершённых матчей игрока
```

## Тесты

```bash
tests/run.sh
```

Скрипт поднимает сервер, прогоняет все наборы и гасит его за собой.
Подробности — в `tests/README.md`.
